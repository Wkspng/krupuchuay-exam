# คู่มือตรวจสอบค่าใช้จ่ายและวิเคราะห์การใช้งาน (Cost Monitoring & Log Guide)

คู่มืออธิบายการบริหารจัดการ ควบคุมค่าใช้จ่าย และการเรียกดูข้อมูล Logs ของระบบ Moonlight Exam

---

## 1. จุดประหยัดค่าใช้จ่ายที่ได้พัฒนาไปแล้ว
ระบบได้รับการอัปเกรดเพื่อลด Firestore Reads/Writes ในจุดสำคัญดังนี้:
1. **Users Scan Prevention**: ระบบค้นหาบัญชีแอดมินและการเปิดหน้าจัดการผู้ใช้งาน จะใช้ระบบแบ่งหน้า (Cursor Pagination) ดึงข้อมูลครั้งละ 20 รายการ แทนการดึงผู้ใช้ทั้งหมดในครั้งเดียว
2. **Attempts Pagination**: รายการประวัติการทำข้อสอบจะใช้วิธี Cursor Pagination ตามการเลื่อนอ่านจริงของผู้ใช้งาน แทนการโหลดครั้งละ 1,000 ชิ้น
3. **Stats Summary Pre-aggregation**: ย้ายระบบแสดงผลหน้าแผงข้อมูลของฉัน (Stats) ไปเก็บบันทึกสรุปแยกที่เอกสาร `userStatsSummary/{userId}` ทำให้เกิด Reads เพียง **1 Read** แทนการรันประวัติการทำข้อสอบมาประมวลผลใหม่ทุกครั้ง
4. **Exam Pack Optimization**: ผู้ใช้งานทำข้อสอบจะดาวน์โหลดจาก Chunked Exam Packs (Reads สูงสุด 2-3 Reads) ป้องกันการถูกเรียกอ่านข้อสอบนับร้อยชิ้นโดยไม่จำเป็น
5. **Rate Limiting**: ช่วยป้องกัน Bot หรือผู้ไม่ประสงค์ดีรันสคริปต์สแกนคำตอบจนบิลพุ่งสูง

## 2. วิธีการดูผลการใช้งาน (Cloud Run logs)
แอดมินสามารถตรวจสอบการเรียกใช้ API และข้อมูลผิดปกติผ่าน Google Cloud Console:
1. ไปที่ [Google Cloud Console Logs Explorer](https://console.cloud.google.com/logs/query)
2. กรองข้อมูล Log ของ Cloud Run Service ชื่อ **krupuchuay-exam-api**
3. ตัวอย่างการใช้เงื่อนไขตรวจสอบ Log การใช้งานแบบสรุป JSON:
   `jsonPayload.logType="API_USAGE"`

### 🔍 จุดสังเกตในข้อมูล Log
- **appCheckStatus**: บ่งบอกสถานะการเชื่อมต่อความปลอดภัย
  - `valid`: ส่งมาจากแอปพลิเคชันจริงและผ่านเกณฑ์ตรวจสอบ
  - `missing`: คาดว่าส่งมาจากสคริปต์ภายนอกหรือผู้ใช้ที่ไม่ได้เปิดใช้งาน App Check
  - `invalid`: ส่งใบอนุญาตปลอมเข้ามา
- **rateLimited**: หากเป็น `true` บ่งบอกว่าผู้ใช้รายนี้ถูกสกัดกั้นด้วยรหัสผลลัพธ์ HTTP 429 เนื่องจากยิงคำขอถี่ผิดปกติ

## 3. รายการ API Endpoint ที่ควรติดตามใกล้ชิด
- `/api/questions/random` (สุ่มข้อสอบ)
- `/api/exam-sets/:id/start` (เริ่มทำข้อสอบชุดวิชา)
- `/api/exam-attempts` (ส่งคะแนนกระดาษคำตอบ)
- `/api/stats/me` (เข้าหน้าจอสถิติ)
- `/api/users` (โหลดหน้าแอดมินจัดการบัญชี)

## 4. แผนตั้งแจ้งเตือนงบประมาณ (Budget Alert Setup)
> [!IMPORTANT]
> **ข้อควรระวังหลัก**: ระบบ Budget Alert ใน Google Cloud Platform เป็นเพียงระบบ **แจ้งเตือนความเสี่ยงผ่านอีเมลเท่านั้น** หากตั้งยอดเงินไว้และเกินวงเงินระบบจะ **ไม่ตัดการทำงานของเซิร์ฟเวอร์โดยอัตโนมัติ** แอดมินต้องเป็นผู้เข้าไปตรวจสอบและดำเนินการระงับการทำงานเอง

### วิธีตั้งค่า Budget Alert งบประมาณเริ่มต้นที่ $10/เดือน
1. ไปที่เมนู **Billing** ใน Google Cloud Console
2. เลือกแถบเมนู **Budgets & alerts** ด้านซ้าย
3. คลิกปุ่ม **Create Budget**
4. ตั้งงบประมาณสูงสุด (Target amount) เป็นยอดเงินที่เรายอมรับได้ เช่น **10 USD** (ประมาณ 350-360 บาท)
5. ตั้งค่าเกณฑ์แจ้งเตือนผ่านอีเมล (Trigger alerts) เมื่อปริมาณค่าใช้จ่ายจริงแตะระดับ:
   - **25%** ของงบประมาณ
   - **50%** ของงบประมาณ
   - **80%** ของงบประมาณ
   - **100%** ของงบประมาณ
6. คลิก **Finish** เพื่อบันทึกการทำงาน

## ⚠️ คำเตือนเรื่องการเปิดใช้งาน App Check Enforce
- ในขั้นตอนเริ่มต้น ระบบตั้งโหมดความปลอดภัยเป็น **Monitor** (เฝ้าสังเกตการณ์) ไว้เท่านั้น
- **ห้ามเปลี่ยนค่าสภาพแวดล้อมให้เป็น Enforce (บังคับสกัดกั้น) เด็ดขาด** จนกว่าจะมั่นใจว่าทราฟฟิกของผู้ใช้จริงเปลี่ยนสถานะเป็น `valid` ทั้งหมดต่อเนื่องอย่างน้อย 1-2 สัปดาห์ เพื่อป้องกันไม่ให้ผู้ใช้จริงเข้าใช้งานระบบไม่ได้เนื่องจากการบล็อกที่ผิดพลาด
