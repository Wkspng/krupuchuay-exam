# คู่มือแก้ไขปัญหาเบื้องต้น (Troubleshooting Guide)

คู่มือรวบรวมแนวทางการแก้ไขปัญหาและการตรวจสอบเบื้องต้นสำหรับผู้ดูแลระบบ Moonlight Exam

---

## 1. ปัญหาด้านการเข้าใช้งานระบบ (Login & Auth)

### ⚠️ ผู้ใช้แจ้งว่า "ล็อกอินไม่ได้" หรือขึ้นว่าระบบขัดข้อง
- **กรณีที่ 1: ผู้ใช้กรอกเฉพาะชื่อหรือ username สั้นๆ**
  - *วิธีแก้*: แจ้งให้ผู้ใช้งานกรอก **อีเมลตัวเต็ม** (เช่น `test11@gmail.com` แทนการกรอกแค่ `test11`)
- **กรณีที่ 2: บัญชียังไม่ได้รับการอนุมัติ (Pending)**
  - *วิธีแก้*: ให้แอดมินเข้าไปหน้าจัดการผู้ใช้งาน แล้วตรวจสอบดูว่าบัญชีนั้นยังอยู่ในหมวดรออนุมัติหรือไม่ หากอยู่ให้กด Approve เพื่อปลดล็อก
- **กรณีที่ 3: บัญชีถูกปฏิเสธสิทธิ์ (Rejected)**
  - *วิธีแก้*: หากเกิดจากการกดปฏิเสธผิดพลาด แอดมินต้องเปิด Firebase Console เข้าไปแก้ไขฟิลด์ `approvalStatus` ของผู้ใช้รายนั้นในคอลเลกชัน `users` ให้กลับเป็น `approved`

---

## 2. ปัญหาด้านข้อมูลข้อสอบ (Exam & Category Update)

### ⚠️ แอดมินเพิ่ม/แก้ไขข้อสอบแล้ว แต่ผู้ใช้งานยังเห็นเป็นข้อสอบเก่า
- **สาเหตุ**: คลังข้อสอบหลังบ้านในระบบ Exam Pack ยังไม่ได้รับการเผยแพร่ใหม่หลังจากแก้ไข
- **วิธีแก้**: แอดมินต้องรันสคริปต์คอมไพล์ชุดข้อสอบบนเซิร์ฟเวอร์เพื่อให้ระบบเขียนแพ็กเกจใหม่:
  ```bash
  # รันอัปเดตทุกหมวดวิชาเพื่อความปลอดภัย
  node scripts/compileExamPacks.js --apply --all
  ```

---

## 3. ปัญหาการปฏิเสธคำขอและหน้าเว็บช้า (Rate Limit & App Check)

### ⚠️ หน้าเว็บค้างหรือแสดงข้อความ "มีการใช้งานถี่เกินไป" (Error 429)
- **สาเหตุ**: อุปกรณ์ของทางผู้เรียนยิงคำขอถี่ยิบเกินเกณฑ์ที่ระบบกำหนดไว้ หรือรันสคริปต์สแกนเว็บ
- **วิธีแก้**: แจ้งให้ผู้ใช้รอคอยอย่างน้อย 10-15 นาทีเพื่อให้รอบเวลาปลดล็อกอัตโนมัติทำงาน หากมีผู้ใช้งานจริงติดหน้าจอนี้จำนวนมากแอดมินอาจพิจารณาขยายขีดจำกัดสิทธิ์ในไฟล์ `middleware/rateLimiter.js` และ Deploy Cloud Run ใหม่

### ⚠️ ใน Log พบสถานะ App Check เป็น `missing` หรือ `invalid`
- **สาเหตุ**: เว็บไซต์จริงอาจยังไม่ได้ผูกกับ Google reCAPTCHA v3 หรือใช้บนสภาพแวดล้อมอื่น
- **วิธีแก้**: ตรวจสอบการประกาศใช้คีย์ในไฟล์ `public/app.js` และยืนยันสถานะการผูกคีย์ใน Firebase App Check Console (ระหว่างที่ยังไม่ Enforce ข้อมูลนี้จะยังไม่บล็อกผู้เรียนจริง)

## 4. วิธีตรวจสอบสุขภาพระบบภายนอก (Health Check)
แอดมินสามารถพิมพ์ URL ปลายทางดังต่อไปนี้เพื่อยืนยันว่าระบบ Backend และโครงข่าย Cloud Run ทำงานร่วมกันได้ปกติ:
- **Health Check URL**: [https://krupuchuay-exam-api-128921965845.asia-southeast1.run.app/api/health](https://krupuchuay-exam-api-128921965845.asia-southeast1.run.app/api/health)
- *หากสำเร็จจะต้องตอบกลับสถานะ JSON ดังนี้*: `{"status":"ok","database":"firestore","projectId":"..."}`

---

## 5. วิธีการย้อนสถานะระบบหากเกิดปัญหา (Rollback Guide)
หากมีการเขียนโค้ดและทำการ Deploy ระบบเวอร์ชันใหม่แล้วเกิดปัญหา แอดมินสามารถย้อนคืนสภาพเวอร์ชันเดิมได้อย่างปลอดภัยผ่านขั้นตอนดังนี้:

### การ Rollback ฝั่ง Backend (Cloud Run)
1. ไปที่โครงการใน [Google Cloud Run Console](https://console.cloud.google.com/run)
2. เลือกบริการ **krupuchuay-exam-api**
3. ไปที่แท็บ **Revisions**
4. เลือก Revision ชุดเก่าก่อนที่จะมีปัญหา (เช่น `krupuchuay-exam-api-00014-w8k` หรือเก่ากว่า)
5. คลิกปุ่ม **"Manage Traffic"** ปรับสัดส่วนการให้บริการของเวอร์ชันเดิมให้กลับมาเป็น 100% แล้วกดบันทึก

### การ Rollback ฝั่ง Frontend (Firebase Hosting)
1. ไปที่โครงการใน [Firebase Console](https://console.firebase.google.com/)
2. เลือกเมนู **Hosting** ในแท็บ Build
3. ไปที่ส่วน **Release history**
4. มองหารุ่นปล่อยตัวล่าสุดก่อนหน้าที่จะพบปัญหา
5. คลิกไอคอนจุดสามจุดในแถวนั้น แล้วเลือก **Rollback** ระบบจะสลับไฟล์ HTML/JS ทั้งหมดของหน้าบ้านกลับเป็นไฟล์ชุดเดิมทันที
