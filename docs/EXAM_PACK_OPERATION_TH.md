# คู่มือ Compile/Publish Exam Pack

คู่มืออธิบายการบริหารจัดการชุดข้อสอบแพ็กเกจบนระบบคลาวด์ เพื่อประสิทธิภาพความเร็วและจำกัดค่าใช้จ่าย Firestore Reads

---

## 1. Exam Pack คืออะไร?
**Exam Pack** คือการนำคำถามทั้งหมดในแต่ละหมวดวิชามาประกอบรวมกัน (Compile) แล้วแบ่งย่อยจัดเก็บเป็นไฟล์แพ็กเกจขนาดใหญ่ (Chunk) บน Firestore:
- **examPackIndexes**: ทำหน้าที่ระบุรายชื่อไฟล์และข้อมูลจำเพาะ (Metadata) ของแต่ละหมวดวิชา
- **examPackChunks**: จัดเก็บอาร์เรย์ข้อสอบจริงจำนวน 50-100 ข้อต่อเอกสาร (ไม่เกิน 700 KB)

### 📈 ประโยชน์ด้านการจำกัด Reads
เมื่อผู้ใช้ล็อกอินเข้ามาเพื่อทำแบบทดสอบ:
- **ระบบเก่า**: ดึงข้อมูลข้อสอบตรงๆ จากตาราง `questions` ทีละชิ้นตามจำนวนข้อสอบในหมวดนั้นๆ (เช่น ดึง 110 ข้อ เกิด 110 Reads)
- **ระบบใหม่**: อ่านดัชนีชิ้นเดียว และดึงเฉพาะ Chunk ที่ต้องการในหมวดวิชานั้น (เกิด **2 Reads** เสมอ) ช่วยจำกัด Reads ได้กว่า **99.6%**

---

## 2. เมื่อไหร่ที่ต้องเริ่ม Compile ใหม่?
แอดมินจะต้องสั่งรันระบบคอมไพล์ใหม่ทุกครั้งที่มีการเปลี่ยนโครงสร้างข้อมูลในคลังข้อสอบ เช่น:
- **เพิ่ม** ข้อสอบชุดใหม่เข้าไปในคลัง
- **แก้ไข** เนื้อหาโจทย์ ตัวเลือก หรือเฉลย
- **ปิดใช้งาน** ข้อสอบ หรือเปลี่ยน `isActive` เป็น false
- **นำเข้า** ข้อสอบแบบ Bulk Import

---

## 3. วิธีการรันคำสั่งคอมไพล์ผ่าน Command Line

### 🔍 ขั้นตอนทดสอบประเมินผลลัพธ์ (Dry-run)
การทดสอบประเมินโดยยังไม่บันทึกจริงลงในฐานข้อมูล Firestore:
- **ทดสอบทุกหมวดวิชา**:
  ```bash
  node scripts/compileExamPacks.js --dry-run --all
  ```
- **ทดสอบเฉพาะหมวดวิชาที่ต้องการ**:
  ```bash
  node scripts/compileExamPacks.js --dry-run --categoryId <ไอดีหมวดวิชา>
  ```
*ระบบจะคำนวณจำนวนคำถามที่ถูกต้อง จำนวน Chunks ที่จะแบ่ง และขนาดไฟล์โดยประมาณให้แสดงใน Console*

### 💾 ขั้นตอนรันเพื่อใช้งานจริง (Apply)
เมื่อประเมินผลผ่านและไม่มีข้อสอบที่ผิดพลาด ให้สั่งรันเพื่อนำลงฐานข้อมูลจริง:
- **อัปเดตและเผยแพร่ทุกหมวดวิชา**:
  ```bash
  node scripts/compileExamPacks.js --apply --all
  ```
- **อัปเดตเฉพาะหมวดวิชาที่ต้องการ**:
  ```bash
  node scripts/compileExamPacks.js --apply --categoryId <ไอดีหมวดวิชา>
  ```

## ⚠️ ข้อควรระวังและการจัดการข้อผิดพลาด
1. **ระบบความปลอดภัยระหว่างคอมไพล์**: หากระบบคอมไพล์เกิดความล้มเหลวหรือตรวจพบข้อสอบที่เสียหายกลางคัน (เช่น ตัวเลือกไม่ครบ 4 ข้อ) ระบบจะยกเลิกการคอมไพล์ในหมวดนั้นทันที โดยจะ **ไม่ลบหรือทำลายชุดข้อสอบเวอร์ชันเดิม** ที่ผู้ใช้งานกำลังใช้อยู่
2. **ห้ามลบคำถามหลัก**: ห้ามลบข้อมูลข้อสอบในตาราง `questions` เด็ดขาด ให้ใช้การปิดใช้งานแทน
3. **การตรวจสอบผลสัมฤทธิ์**: หลังจากรัน `--apply` สำเร็จ ให้ทดลองเข้าล็อกอินทำแบบทดสอบ หากเป็นระบบจากแพ็กเกจใหม่ ค่าตอบกลับ API สำหรับคิวรีข้อสอบจะมีคีย์ `"generatedFromPack": true` ติดอยู่ด้านหลัง
