# แผนการเปิดทดลองใช้งานกลุ่มย่อย (Soft Launch Pilot Plan) - Moonlight Exam

เอกสารนี้ระบุแนวทางและวิธีการดำเนินโครงการนำร่องเปิดทดลองใช้งานจริงระบบ Moonlight Exam ร่วมกับผู้ใช้งานกลุ่มย่อย เพื่อประเมินความเสถียร ประสบการณ์ผู้ใช้ และความถูกต้องของระบบข้อสอบทั้งหมดภายใต้สภาพแวดล้อมจำลองแบบจำกัด

---

## 🎯 1. เป้าหมายการทดลอง (Pilot Objectives)
1. **ประเมินเสถียรภาพการประมวลผล**: ตรวจสอบการรองรับภาระงานของฐานข้อมูลและสถาปัตยกรรมคลังข้อสอบ (Exam Packs) เมื่อมีผู้ใช้พร้อมกัน
2. **วัดความก้าวหน้าและการตรวจคะแนน**: ตรวจสอบความถูกต้องของสถิติย้อนหลัง ประวัติการทำข้อสอบ และอัตราความเร็วการวิเคราะห์ผลลัพธ์
3. **เก็บรวบรวมฟีดแบค**: ศึกษาความยากง่ายในการเข้าถึงของผู้ใช้ และระบุปัญหาที่อาจเกิดบนอุปกรณ์โทรศัพท์มือถือที่หลากหลาย

---

## 👥 2. รายละเอียดผู้ใช้และกรอบเวลา (Target Group & Timeline)
* **จำนวนกลุ่มทดลอง**: 5 – 20 คน (ประกอบด้วยนักศึกษาฝึกประสบการณ์วิชาชีพครู และบุคลากรที่เตรียมสอบครูผู้ช่วย)
* **ระยะเวลาทดลอง**: 3 – 7 วัน
* **วันที่คาดว่าจะดำเนินการ**: 6 กรกฎาคม 2026 – 12 กรกฎาคม 2026

---

## 🛠️ 3. ขั้นตอนการเข้าใช้งานระบบนำร่อง

### 3.1 การสมัครสมาชิก (Registration)
1. ให้ผู้ทดลองเปิดลิงก์ระบบทดลอง: `https://moonlight-krupuchuay-exam.web.app`
2. คลิกปุ่ม **สมัครสมาชิก (Register)**
3. กรอกข้อมูลส่วนตัว: Username, Password และชื่อสกุลให้ครบถ้วน
4. เมื่อสมัครสำเร็จ ระบบจะแสดงข้อความว่า **"รอการอนุมัติการใช้งานจากแอดมิน"**

### 3.2 การอนุมัติสิทธิ์การเข้าทำข้อสอบ (Admin Approval)
1. ผู้ดูแลระบบ (Admin) เข้าสู่ระบบผ่านช่องทางแอดมินพอร์ทัล
2. ไปที่หน้าจัดการผู้ใช้งาน (User Management)
3. ตรวจสอบรายชื่อและคลิกอนุมัติสิทธิ์ (Approve) ให้ผู้ทดสอบมีสถานะเป็น `approved`
4. แจ้งผู้ใช้รับทราบทางกลุ่มประสานงานเพื่อเข้าล็อคอินรอบที่สอง

---

## 📝 4. รายการที่ผู้ใช้งานต้องดำเนินการทดสอบ (User Testing Checklists)
ผู้ทดลองทุกคนจะได้รับมอบหมายให้ทำกิจกรรมดังต่อไปนี้:
* [ ] ลงทะเบียนบัญชีใหม่และรอรับการอนุมัติสิทธิ์
* [ ] ล็อคอินเข้าสู่ระบบผ่านคอมพิวเตอร์และโทรศัพท์มือถืออย่างละ 1 ครั้ง
* [ ] ทดลองทำข้อสอบให้ครบทุกภาคส่วน (Part 1, 2, และ 3) อย่างน้อยภาคละ 1 ครั้ง (เลือกทำหมวดใดก็ได้)
* [ ] ทำข้อสอบจนส่งคำตอบ (Submit) และเปิดดูหน้าสรุปคะแนนเฉลยละเอียด
* [ ] เข้าหน้าจอสถิติ (Stats & History) เพื่อยืนยันว่าประวัติคะแนนของตนเองขึ้นแสดงถูกต้อง
* [ ] ลองทำข้อสอบซ้ำในหมวดเดิมเพื่อยืนยันว่าสถิติดับคะแนนสูงสุดอัปเดตสอดคล้องกัน

---

## 📣 5. การส่งรายงานและฟีดแบค (Reporting System)
* **การส่งข้อร้องเรียน/พบบั๊ก**: ให้ดาวน์โหลดและกรอกข้อมูลตามเอกสาร `docs/BUG_REPORT_TEMPLATE_TH.md` แล้วส่งผ่านกลุ่มประสานงานหลัก
* **การประเมินความพึงพอใจ**: เมื่อครบกำหนดระยะเวลาการทดสอบ ให้ผู้ทดสอบทุกคนตอบคำถามตามหัวข้อในแบบฟอร์ม `docs/USER_FEEDBACK_TEMPLATE_TH.md`

---

## 🏁 6. เกณฑ์การผ่านประเมินเพื่อเปิดใช้งานอย่างเป็นทางการ (Launch Criteria)
ระบบจะได้รับการรับรองว่าพร้อมให้บริการจริงแก่ผู้ใช้จำนวนมาก หากผ่านเงื่อนไขดังต่อไปนี้:
1. **Critical Bugs = 0**: ไม่พบบั๊กใดๆ ที่ทำให้ระบบใช้งานไม่ได้ หรือทำให้การคำนวณคะแนนและประวัติผิดพลาด
2. **API Success Rate > 99.5%**: การบันทึกและสุ่มข้อสอบผ่าน API ทำงานราบรื่นโดยไม่พบข้อผิดพลาดระดับ Server Error (500)
3. **User Satisfaction > 85%**: ผลตอบรับด้านความสะดวกในการใช้งานบนอุปกรณ์พกพามือถือเป็นที่ยอมรับ
4. **Backend Performance Guard**: อัตรา Firestore read/write สะท้อนการประหยัดสถิติ reads ด้วยระบบจัดทำ Exam Packs ที่เสถียร
